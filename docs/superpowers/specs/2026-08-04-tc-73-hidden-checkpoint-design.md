# TC-73: запуск точки обслуживания в скрытом режиме

## Цель

Автоматизировать Kiwi TCMS TC-73 «Включение точки обслуживания в скрытом режиме» как один Playwright E2E-тест, соответствующий текущему интерфейсу стенда. Устаревшие варианты запуска «сейчас», «в установленные часы» и «в часы работы очереди» в тест не входят. Дополнительно тест подтверждает, что скрытая точка не создаёт собственную ёмкость для предварительной записи, но может обслуживать позиции, записанные благодаря параллельно работающей обычной точке.

## Размещение и повторное использование

Тест добавляется в `specs/admin/checkpoint-cases.spec.ts` и запускается в существующем serial-наборе кейсов точек обслуживания. Для подготовки, API-проверок и очистки используются существующие функции создания точки, регистрации сущности в `.e2e-stand-state.json`, чтения `/api/GetCheckpointList`, остановки точки и удаления позиций. Проверка слотов выполняется через пользовательскую форму создания записи и ответ `/api/positionsManagement/getServiceDateTimes`, чтобы одновременно подтвердить серверный результат и его отображение в интерфейсе.

## Сценарий

1. Авторизоваться в Backoffice.
2. Создать две уникальные точки в подготовленной остановленной очереди: скрытую и обычную. Обе точки зарегистрировать для общей очистки, обычную оставить выключенной.
3. Открыть параметры скрытой точки и выбрать действие запуска в скрытом режиме через стабильный `data-test` локатор.
4. Заполнить только те параметры запуска, которые фактически доступны в текущем интерфейсе стенда: выбрать услугу, заполнить обязательную причину и изменить доступную настройку скрытого режима, если она отображается.
5. Сохранить настройки и дождаться успешного ответа `/api/updateCheckpointHost`.
6. Дождаться, пока API списка точек вернёт скрытую точку с `status === "started"` и `isHidden === true`; проверить выбранную услугу и доступные параметры.
7. Открыть пользовательскую форму создания записи, выбрать услугу и дождаться загрузки тайм-слотов. Убедиться, что при единственной работающей скрытой точке API не возвращает слоты на текущую дату, а интерфейс сообщает об отсутствии свободного времени.
8. Запустить вторую точку в обычном режиме с той же услугой и дождаться `status === "started"` и `isHidden !== true`.
9. Повторно открыть форму создания записи. Убедиться, что на текущую дату появились тайм-слоты, выбрать первый доступный слот и создать уникальную запись через интерфейс.
10. Открыть мониторинг скрытой точки, найти созданную позицию и выполнить полный цикл обслуживания: готовность, вызов, начало обслуживания и завершение обслуживания.
11. Проверить, что завершённая позиция исчезла из мониторинга очереди.
12. В блоке `finally` удалить незавершённую тестовую позицию при необходимости и остановить обе точки, даже если основная проверка завершилась ошибкой.

## Локаторы

Основные действия выполняются через существующие `data-test` атрибуты:

- `CheckpointHost-Action-startHidden` — выбор скрытого режима;
- `CheckpointHost-AllServices` — выбор услуг;
- `CheckpointHost-ReasonHiddenStart` — причина скрытого запуска, если поле отображается;
- `CheckpointHost-HiddenStartAllowCreatePosition` — настройка создания позиций в скрытой точке, если она присутствует в текущем интерфейсе;
- `CheckpointHost-ApplyButton` — применение параметров.

Текстовые локаторы допустимы только для бизнес-состояний, у которых в текущей реализации нет `data-test`: индикатор скрытого режима, сообщение об отсутствии слотов, отображаемое время, тестовая позиция и действия её обслуживания.

## Проверки

Тест считается успешным, если одновременно выполняются условия:

- запрос обновления точки завершился успешно;
- точка перешла в состояние `started`;
- API возвращает `isHidden === true`;
- выбранная услуга включена для точки;
- интерфейс показывает, что точка работает в скрытом режиме;
- при работающей только скрытой точке отсутствуют слоты записи на текущую дату;
- после запуска обычной точки на текущую дату появляются слоты записи;
- запись успешно создаётся в слот, сформированный обычной точкой;
- созданная позиция отображается в мониторинге скрытой точки;
- скрытая точка позволяет выполнить полный цикл обслуживания этой позиции;
- завершённая позиция исчезает из активного мониторинга.

## Ошибки и очистка

Ожидания перехода состояния и завершения позиции выполняются опросом API с ограниченным таймаутом. При падении теста `finally` пытается удалить позицию и остановить обе точки; созданные точки остаются зарегистрированными в состоянии стенда и будут удалены штатным `stand:cleanup`. Ошибки очистки не должны скрывать исходную ошибку теста.

## Документация и видео

После реализации описание TC-73 добавляется в `TESTS.md`. Тест запускается отдельно с включённым видео и замедлением действий; итоговый `.webm` сохраняется в `artifacts/kiwi-checkpoints/`. Флаг `is_automated` в Kiwi TCMS меняется только после проверки видео пользователем.
